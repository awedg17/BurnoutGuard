# BurnoutGuard — AI Agent Knowledge Base

> This document contains everything an AI agent needs to understand, maintain, and extend the BurnoutGuard prototype.

---

## 1. Project Overview

**BurnoutGuard** is a web app prototype that helps college students manage academic workload and detect burnout risk based on activities, deadlines, priority, mood, and energy.

- **Tech Stack**: TanStack Start v1 (React 19 + Vite 7), Tailwind CSS v4, shadcn/ui, Recharts, local state only (no backend)
- **Purpose**: Demoable prototype with clear user flow
- **Target Users**: College students (Indonesian context — categories like "Kuliah", "Organisasi", "Skripsi")
- **No onboarding, no support/emergency page**
- **Responsive**: Desktop (top nav) + Mobile (bottom nav)

## 5. Business Logic

### Date Helpers
- `todayISO()` → `yyyy-mm-dd` for today at midnight
- `daysUntil(deadline)` → integer days from today (negative = overdue)
- `dueLabel(deadline)` → human string: "Due today", "Due tomorrow", "3d overdue", etc.

### Activity Ranking (Priority Logic)
```ts
rankScore(activity) = priorityWeight × urgency
// urgency = 11 if overdue, else 10 - min(daysUntil, 9)
// So: overdue = ×11, today = ×10, tomorrow = ×9, 7 days = ×3
```

`rankActivities()` filters out `completed`, sorts by `rankScore` descending.

### Burnout Risk Calculation (`computeRisk`)

**Step 1 — Base scores (0–100 each):**
- `loadScore` = min(100, activeCount × 11)
- `deadlineScore` = min(100, closeDeadlines × 14 + overdue × 22)
- `priorityScore` = min(100, highPriorityCount × 22)
- `wellbeingScore` = ((5−mood)/4)×50 + ((5−energy)/4)×50 (only if check-in exists)

**Step 2 — Weighted total:**
- WITH check-in: load×0.25 + deadline×0.30 + priority×0.20 + wellbeing×0.25
- WITHOUT check-in: load×0.34 + deadline×0.40 + priority×0.26

**Step 3 — Risk levels:**
- 0–39: Low Risk
- 40–69: Medium Risk
- 70–100: High Risk

**Summaries by level:**
- Low: "Your workload and wellbeing look balanced right now. Keep your steady rhythm."
- Medium: "A few deadlines and priorities are stacking up. Plan your week so it stays manageable."
- High: "Several close deadlines and high-priority tasks are adding pressure. Consider rebalancing soon."

### Recommendations (`src/lib/recommendations.ts`)

`getTodayRecommendation(activities)`:
- Returns 1 sentence focusing on the top-ranked activity
- Example: `Focus on finishing "Proposal AI" first because it has high priority and is due in 3 days.`

`getRecommendations(risk, activities)`:
- Returns up to 4 practical, non-medical tips
- Covers: top task, overdue items, clustered deadlines, overlapping high-priority tasks, missing check-in, high-risk suggestion, low-risk encouragement

## 6. Page Specifications

### Home (`/`) — `src/routes/index.tsx`

**Layout**: `grid gap-6 md:grid-cols-5`
- Left column (2 cols): Risk Gauge card
- Right column (3 cols): Today's Recommendation + Quick Check-in
- Below full-width: Today's Priorities

**Sections:**
1. **Greeting**: "Welcome back 👋" + "Here's how your week feels"
2. **Burnout Risk Status Card**:
   - `<RiskGauge>` SVG circular progress (size 180)
   - Badge showing level + score/100
   - Short summary text
   - Info note if no check-in today
3. **Today's Recommendation**: Card with Lightbulb icon + 1 actionable sentence
4. **Quick Check-in**: Card with Sparkles icon
   - Mood selector: 3 buttons (Happy 🙂, Neutral 😐, Tired 😔)
   - Energy slider: 1–5
   - "Save check-in" button → triggers toast + recomputes risk
5. **Today's Priorities**: Top 3 from `rankActivities()`
   - Numbered badges, title, category, priority label
   - Due badge (red if ≤1 day)
   - "All activities →" link

### Activities (`/activities`) — `src/routes/activities.tsx`

**Features:**
- Add / Edit / Delete / Change status
- Two views: List and Calendar (Tabs switcher)
- Custom category creation

**List View:**
- Sorted by: incomplete first, then by deadline closeness
- Each card: title, description, category badge, priority badge, due label
- Edit (pencil) and Delete (trash) buttons
- Status dropdown: To Do / In Progress / Completed
- Completed items have `opacity-60` and `line-through`

**Calendar View:**
- Month grid with prev/next navigation
- Days show dots for activities due that date
- Clickable to edit

**Add/Edit Dialog:**
- Title (required)
- Category (select from existing OR add new)
- Deadline (date picker)
- Priority (Low/Medium/High)
- Status (To Do/In Progress/Completed)
- Description (optional textarea)

**Important SSR Fix:** In the ListView status `<Select>`, the `<SelectValue>` is explicitly rendered as `<SelectValue>{STATUS_META[a.status].label}</SelectValue>` to avoid Radix UI hydration mismatches during SSR.

### Insights (`/insights`) — `src/routes/insights.tsx`

**Sections:**
1. **Stats Cards** (2×2 grid → 4 cols on desktop): Total, Completed, Active, Overdue
2. **Burnout Risk Trend** (AreaChart, 3/5 width):
   - X-axis: Mon–Today
   - Y-axis: 0–100
   - Gradient fill under line
   - Risk level badge in header
3. **Category Distribution** (PieChart, 2/5 width):
   - Donut chart with legend
   - Colors: chart-1 through chart-5
4. **Burnout Factors** (full-width card):
   - 4 progress bars: Active activities, Close deadlines, High-priority load, Mood & energy
   - Color coding: calm (<40), warning (40–69), danger (≥70)
5. **AI Recommendation** (full-width card, `bg-secondary/40`):
   - Bulleted list of up to 4 tips
   - Disclaimer: "not a medical diagnosis"

## 10. Constraints & Rules

1. **No backend** — all data is local React state (seeded at mount)
2. **No onboarding flow** — app is usable immediately

4. **Light theme only** — no dark mode implementation

## 11. Common Tasks for AI Agents

### Adding a New Page
1. Create `src/routes/page-name.tsx` with `createFileRoute('/page-name')`
2. Export `Route` with `head()` for SEO meta and `component`
3. Import in `src/router.tsx` is NOT needed — file-based routing auto-registers
4. Add nav link in `AppLayout.tsx` if it should be in the main nav

### Modifying the Risk Algorithm
- Edit `computeRisk()` in `src/lib/burnout-store.tsx`
- Keep score 0–100, level mapping consistent
- Update `summary` strings if levels change meaning

### Adding New Activity Fields
1. Update `Activity` interface in `burnout-store.tsx`
2. Update form state and dialog in `activities.tsx`
3. Update seed data if needed

### Changing Colors
- ONLY edit `src/styles.css` `:root` variables
- NEVER hardcode colors in component files
- Use semantic tokens: `--primary`, `--calm`, `--warning`, `--danger`
